# VulnFounder 官方 24 个历史样本动态测试泛化优化方案

> 文档类型：实施计划
> 目标：不依赖单个样本的硬编码协议帧，让官方 24 个历史样本完成可审计的动态验证闭环。
> 当前基线：evaluation_dataset/vulnerability/result/BOARD_OFFICIAL_24_CLEAN_ROOM_DYNAMIC_TEST_20260921.zh-CN.md
> 状态：待评审后实施。

## 1. 结论和目标

当前实现还不能称为通用动态测试器。24 个样本中只有 1 个 CONFIRMED，另外 23 个在设备载荷发送前终止：17 个缺少协议或入口证据，6 个缺少 resource_delta 预言机。

这不意味着整个框架需要推倒重来。现有的 clean-room 隔离、动态会话编排、HAP 构造、设备监控、历史产物和文件差分都可以保留。真正需要重构的是三个核心环节：

1. 从源码和设备事实恢复可执行协议，而不是依赖 sp_daemon_text 等特例描述符；
2. 让不同漏洞类型使用匹配的输入影响和安全效果预言机，而不是默认观察 marker 文件；
3. 显式记录服务版本、服务状态、运行身份和协议不确定性，避免把“没有执行”写成“没有漏洞”。

最终目标不是强行让 24 个样本全部显示 CONFIRMED，而是让 24 个样本都完成真实、可解释的验证流程：

- 24/24 都有设备环境和版本结论；
- 版本匹配且服务可用的样本进入实际设备发送阶段；
- 每个实际发送的样本都有源码证据、协议契约、真实载荷、设备回执和对应预言机；
- 版本不匹配、服务缺失或设备能力不足的样本输出可证明的环境结论；
- clean-room 不读取该样本的人工攻击链、历史成功帧或同样本 exemplar。

## 2. 当前基线和问题分层

| 现象 | 数量 | 直接表现 | 根因 |
|---|---:|---|---|
| 协议/入口恢复失败 | 17 | REQUIRES_PROTOCOL_REVIEW | 没有从接收函数、分帧、字段解析一直恢复到危险参数，或事件总线缺少外部发布端点 |
| 预言机缺失 | 6 | ORACLE_UNAVAILABLE: resource_delta 未实现 | 越界、资源、管道、状态变化没有对应观测器 |
| 实际设备执行 | 1 | DP-02 既有 run | SmartPerf 文本协议、HAP 发送和文件差分已经形成闭环 |
| 服务不稳定 | 1 类服务 | SP_daemon 曾短暂监听 8283/8284/8285 后退出 | 服务健康没有成为运行前置条件 |

本轮 23 个新 run 都没有达到 ELIGIBLE，因此不能得出 23 个样本不存在或不可利用。后续必须区分 CONTRACT_UNRESOLVED、SERVICE_UNAVAILABLE、VERSION_MISMATCH、ORACLE_UNSUPPORTED 和 NOT_REPRODUCED。

## 3. “跑通 24 个样本”的分层定义

| 层级 | 名称 | 必须满足 | 是否等同于漏洞确认 |
|---|---|---|---|
| L0 | 环境可审计 | 设备、固件/二进制、服务、权限身份均有记录 | 否 |
| L1 | 契约可执行 | 入口、传输、分帧、字段和发送方式通过源码与合法探针校验 | 否 |
| L2 | 输入已送达 | 设备确认收到输入，并观测到对应处理函数或协议回执 | 否 |
| L3 | 效果已归因 | 预言机证明危险参数受输入影响，并观察到匹配的安全效果 | 是，才可 CONFIRMED |

验收要求：24/24 完成 L0；版本匹配且服务可用的样本完成 L1/L2；L3 根据设备是否包含该问题和效果是否可观测分别判定。设备不匹配时不得强行进入 L3。

## 4. 目标架构

```
静态 finding 和源码证据
    -> 样本标准化
    -> 设备版本、服务、身份预检
        -> 匹配且可用：协议恢复 Agent Loop
        -> 不匹配或服务缺失：环境结论
    -> 路由候选与协议契约
    -> 源码约束校验
        -> 失败：新增补证任务并重新检索
        -> 通过：生成合法探针
    -> 设备侧探针验证
        -> 未到达：修正契约或记录缺口
        -> 到达：生成单变量变异载荷
    -> 输入影响验证
    -> 漏洞类别预言机
    -> CONFIRMED / NOT_REPRODUCED / INCONCLUSIVE / 环境结论
    -> 清理、归档和历史页面
```

协议恢复、设备探针、输入影响和漏洞效果不能再共用一个黑盒编译门槛。每层都要产出证据，并把失败反馈给下一轮任务树。

## 5. 统一样本契约

每个样本先转换为统一的 DynamicFindingContract，内容包括：

- sample_id、扫描来源和目标函数；
- 漏洞类别、危险操作和危险参数；
- 当前 finding 的源码证据和候选入口；
- 候选传输方式与服务端处理函数；
- 预计安全效果和所需身份；
- 参考源码 revision、设备 revision 和版本判定；
- 当前未决问题和已尝试动作。

约束：

- 证据只来自当前扫描产物、当前源码读取和本轮设备探针；
- 入口和路由允许保留多个候选，不能只保留模型最先想到的一条；
- required_effect 由漏洞类别决定，不能所有样本都默认 marker；
- 普通应用、shell、系统服务和 root 必须区分；
- 源码版本与设备版本不一致时，进入版本分支，不得直接判定 NOT_REPRODUCED。

## 6. 协议恢复 Agent Loop

### 6.1 动态任务树

根任务只有一个：恢复当前 finding 对应服务端的可执行输入协议。模型根据证据动态生成子任务，常见任务包括：

- 定位端点创建、获取或注册位置；
- 定位 accept、recv、recvfrom、read 和消息循环；
- 恢复分帧、分隔符或二进制布局；
- 恢复字段解析和类型转换；
- 恢复命令、事件或消息分派；
- 追踪字段到危险参数的来源；
- 生成无害合法探针；
- 选择漏洞类别对应的预言机。

如果新证据出现第二个入口、第二个字段或另一种传输方式，必须动态新增任务和路由候选，而不是套用固定七节点。

### 6.2 每轮上下文

模型每轮应看到：

1. 目标函数完整源码和精确位置；
2. 已确认的上游和下游函数源码；
3. 所有入口候选、路由候选和证据等级；
4. 已执行命令、输出摘要和失败理由；
5. 当前任务树、未决任务和剩余预算；
6. 设备端点、进程、UID、SELinux、服务状态和能力；
7. 协议描述符和预言机 schema；
8. 上一轮被校验拒绝的字段以及拒绝原因。

clean-room 禁止提供样本人工攻击链、历史成功 payload、预写 frame 字符串或只为通过评测而加入的目标路径。

### 6.3 工具和强制输出

工具包括源码定义搜索、引用搜索、函数读取、文件读取、函数索引、设备只读探针和契约提交。每一个源码关系必须引用路径与行号；函数列表存在不能代替调用关系证据。

每轮模型输出必须包含：新任务、证据引用、路由候选、字段映射、合法探针、单变量变异、预期预言机、未决假设和下一步动作。禁止只返回一串攻击帧。

### 6.4 失败反馈

| 失败 | 下一步 |
|---|---|
| 端点未验证 | 查询 bind、socket 创建和设备监听状态 |
| 字段不存在 | 回到接收与解析函数，删除模型虚构字段 |
| 字段不能到达 sink | 追踪赋值、成员、全局状态、回调参数 |
| 探针无回执 | 尝试其他候选路由或修正分帧 |
| 合法帧被拒 | 读取源码守卫、token、长度和命令条件 |
| HAP 编译失败 | 修复载荷类型，不更换漏洞目标 |
| 服务未运行 | 停止发送，有限重启并重新健康检查 |
| 预言机缺失 | 使用匹配 oracle，或输出 ORACLE_UNSUPPORTED |

同一失败签名最多重试 3 次。达到预算后保留未决任务和证据，不能生成虚假契约。

## 7. 协议族适配器

协议描述符使用统一 schema 表达 endpoint、receiver、framing、fields、dispatch、guards 和 assumptions，不再把 sp_daemon_text 作为默认答案。

### 7.1 UDP/TCP 文本协议

自动恢复端点、连接方式、帧边界、分隔符、命令字、守卫条件和响应。只有源码出现真实字符串或解析表达式，才能生成字段。SmartPerf 的具体命令只能是源码恢复结果，不能成为全局常量。

### 7.2 Unix Domain Socket

区分 SOCK_STREAM、SOCK_DGRAM、路径名、抽象名、匿名 socket、sendmsg/recvmsg 的凭证和 FD 传递，并判断 HAP 是否能访问，还是必须使用授权 native helper。

### 7.3 HiSysEvent/事件总线

不能把进程内 listener 当成外部入口。必须恢复外部发布 API、domain/eventName、字段 schema、序列化方式、权限条件、listener 分派和设备端配置。

### 7.4 CLI、任务和线程

CLI 必须记录真实命令、权限身份和参数解析。线程入口不是天然外部入口，只有任务参数来自已验证外部边界时才可进入 L1。

## 8. 设备预检和服务稳定性

每个样本开始前生成 device_fingerprint.json，至少包含：设备序列号、系统/API/产品版本、目标进程 PID/UID/SELinux 域、二进制 hash、监听端点、服务能力、执行身份、参考 revision 和设备 revision。

SP_daemon 的启动流程必须是：

1. 检查现有 PID；
2. 不存在时在授权条件下无参启动；
3. 等待进程和 8283/8284/8285 监听同时出现；
4. 连续两次健康检查确认驻留；
5. 记录退出码、日志和退出时间；
6. 反复退出时停止相关样本并输出 SERVICE_UNAVAILABLE。

不能因为短暂看到 PID 就开始发送，也不能在服务已经退出后把失败归因给协议或漏洞。

## 9. 设备版本与源码版本核验

每个样本登记参考源码仓库/commit/文件 hash、漏洞与修复差异、设备二进制 hash、版本字符串、运行服务和最终状态。

| 状态 | 含义 | 后续动作 |
|---|---|---|
| MATCHED | 设备二进制或源码与样本版本一致 | 允许进入动态结论 |
| MISMATCH | 明确不是漏洞版本 | 输出 VERSION_MISMATCH，不构造攻击载荷 |
| UNKNOWN | 无法取得足够版本信息 | 输出 VERSION_UNVERIFIED，不称为漏洞不存在 |
| SERVICE_UNAVAILABLE | 服务不存在或不能稳定运行 | 输出服务结论，不把它写成协议失败 |

## 10. 通用载荷和身份执行

HAP 只是传输载体。运行器根据协议选择 HAP UDP/TCP、HAP Unix socket、授权 native helper、CLI 或事件发布工具。

每个载荷必须保存 contract_id、唯一 canary、探针和变异的实际内容、端点、传输、安装/启动/清理命令、运行身份、发送时间、设备回执和 SHA-256。

载荷只能使用契约中的字段。模型没有证据的字段不能写入 HAP；来自固定设备状态的值必须标记 device_derived，不能伪装为 attacker_controlled。

权限样本必须进行身份阶梯。root 下观察到的效果不能直接证明普通应用可利用；无法降权时输出 IDENTITY_UNVERIFIED。

## 11. 输入影响和效果预言机

### 11.1 输入影响

需要回答变异输入是否到达危险参数。可用参数回显、受控日志、canary、差分请求、线程 trace、外部输出 token 关联等证据。仅出现服务日志或函数名，不能证明危险参数受控。

### 11.2 漏洞类别预言机

| 类型 | 观测器 | 确认条件 |
|---|---|---|
| 命令注入 | 文件、进程、命令输出差分 | 唯一 canary 由危险命令产生并绑定服务身份 |
| 任意文件写/路径穿越 | 文件存在、内容、权限和路径差分 | 路径由输入控制且变化与请求时间相关 |
| 越界/崩溃 | faultloggerd、tombstone、信号和服务重启 | 输入已送达且崩溃归因到目标服务 |
| 权限绕过 | 普通应用与高权限双跑 | 低权限请求完成本应拒绝的操作 |
| FD/资源泄漏 | fd、线程、内存、socket 快照 | 重复请求后资源增长并可归因 |
| 信息泄露 | 返回包、日志和文件内容差分 | 受保护数据被输入触发并返回 |
| 竞态/状态错误 | 并发重复运行和状态快照 | 控制变量下稳定产生非法状态差异 |

每个 oracle 都必须包含 before、during、after 和 refutation。无法观测时输出 ORACLE_UNSUPPORTED，不返回泛化 error。

## 12. 24 个样本分组推进

### 12.1 SmartPerf / DP-01～DP-18

| 样本 | 主要改造 | 通过条件 |
|---|---|---|
| DP-01、03、04、07、08、09、10、13、14、15、17 | 从 HandleMsg、命令表、字段解析和业务函数恢复真实字段；禁止生成 frame_fourth、command/host/port 等源码不存在的字段 | 合法探针到达目标处理函数，单字段变异到达危险参数 |
| DP-02 | 正向回归基线，验证不依赖内置 descriptor 仍能自动恢复 | clean-room 自动契约通过并确认 |
| DP-05、06、11、12、16、18 | 补资源、管道、崩溃、状态 oracle，先验证服务版本 | 匹配设备版本时进入 L2/L3，否则输出版本/服务结论 |

SmartPerf 组的目标不是再次手写 set_pkgName 或 catch_network_traffic，而是让源码驱动的恢复器自动发现每个样本的命令条件、字段和 sink 参数。

### 12.2 HiView / HV-01～HV-06

| 样本 | 主要改造 | 通过条件 |
|---|---|---|
| HV-01、HV-02、HV-04 | 恢复外部事件发布端点、domain/eventName、序列化和权限条件 | 事件探针被 listener 接收，并证明字段流入危险参数 |
| HV-03 | 识别真实事件或 Unix socket 协议，不使用空字段描述符 | 合法事件可发送，字段映射和效果 oracle 通过 |
| HV-05 | 恢复文件路径字段和路径穿越影响，补文件差分 oracle | 版本匹配时观察受控路径变化，或输出明确版本结论 |
| HV-06 | 恢复 FreezeManager 外部入口、路径参数和文件写 oracle | 入口、参数、写入结果形成闭环 |

## 13. 分阶段任务和检查点

### 阶段 0：基线与 clean-room

- 建立 24 项清单，关联 scan、sample、仓库、目标函数、漏洞类别、参考 revision 和现有 run。
- 冻结模型输入，仅允许当前 finding、源码证据、通用知识和本轮设备探针。
- 验收：24 项均有唯一身份、源码位置、当前失败原因和可审计 context_sources。

检查点 A：24 项基线完整；clean-room 输入可审计；版本和设备预检 schema 已确定。

### 阶段 1：设备和版本

- 实现设备指纹、目标进程/端点/权限/二进制 hash 采集。
- 实现服务启动、连续健康检查、退出日志和 SERVICE_UNAVAILABLE。
- 实现 MATCHED/MISMATCH/UNKNOWN/VERSION_UNVERIFIED。

检查点 B：24/24 有 L0 记录；版本未知不再被写成漏洞未复现；SP_daemon 不稳定时能早停并给出服务原因。

### 阶段 2：协议恢复

- 统一 UDP、TCP、Unix stream、Unix datagram、事件总线和 CLI 的描述符 schema。
- 实现动态 Agent Loop、源码证据校验、合法探针和失败反馈。
- 验收：字段缺失、端点未证实和模型虚构字段全部被拒绝；协议缺口进入后续任务，不直接终止。

检查点 C：24/24 有协议候选或明确环境阻断；所有实际帧均可追溯到源码字段证据。

### 阶段 3：载荷和身份

- 按契约自动选择 HAP、native helper、CLI 或事件发布器。
- 生成实际载荷清单和清理动作。
- 对权限类样本执行普通应用与高权限对照。

### 阶段 4：预言机

- 实现 FD、内存、线程、管道、socket 快照差分。
- 接入 faultloggerd、tombstone、服务重启、文件路径差分和权限差分。
- 实现输入影响 oracle 和 refutation。
- 验收：6 个 resource_delta 缺口不再返回 ORACLE_UNAVAILABLE。

### 阶段 5：分批回归

执行顺序：DP-02 基线；SmartPerf 协议组；SmartPerf 资源/崩溃组；HiView 事件/Unix socket 组；最后全量 24 项 clean-room 回归。

每批必须保存源码版本、设备状态、模型输入输出、探针、实际载荷、预言机和清理结果。

## 14. 验收矩阵

| 指标 | 当前基线 | 第一阶段目标 | 最终目标 |
|---|---:|---:|---:|
| 历史中有终态 | 24/24 | 24/24 | 24/24 |
| L0 环境可审计 | 未统一 | 24/24 | 24/24 |
| 契约可执行 L1 | 1/24 | 至少 18/24 | 匹配样本 100% |
| 输入已送达 L2 | 1/24 | 至少 12/24 | 匹配样本 100% |
| 有匹配 oracle | 18/24 | 24/24 | 24/24 |
| ORACLE_UNAVAILABLE | 6 | 0 | 0 |
| 无解释的通用 error | 23 | 0 | 0 |
| CONFIRMED | 1/24 | 以设备版本为条件 | 只在输入影响和安全效果均证实后统计 |

不设置“必须 24/24 CONFIRMED”的不安全指标。正确目标是：设备确实包含、版本匹配、入口可达且效果可观测的样本应确认；其他样本必须给出可复查的版本、服务或证据结论。

## 15. 反作弊和安全约束

- 不把 24 个样本清单作为模型目标答案；
- 不把人工攻击链、既有成功帧或历史 exemplar 传入 clean-room；
- 不允许模型凭函数名生成不存在的字段、端点或命令；
- 每个变异字段必须有源码表达式、字段解析位置和探针证据；
- 每个效果绑定唯一 canary、服务 PID、时间窗口和 before/after 快照；
- root 效果不能自动升级为普通应用可利用；
- 版本未知不能输出漏洞不存在；
- 服务未运行不能把失败归因于协议；
- 所有载荷都有清理记录和远程路径白名单。

## 16. 风险和应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 开发板不是漏洞版本 | 误把环境差异当动态失败 | 二进制/版本指纹，输出 VERSION_MISMATCH |
| SP_daemon 启动后退出 | SmartPerf 组无法执行 | 健康检查、有限重启、退出日志，输出 SERVICE_UNAVAILABLE |
| 私有事件协议无法唯一恢复 | HiView 契约不确定 | 保留多个候选，要求合法探针，不直接发攻击帧 |
| HAP 无法模拟真实身份 | 权限类结果失真 | 普通应用与高权限对照，输出 IDENTITY_UNVERIFIED |
| 预言机误报 | 把普通行为当漏洞效果 | 唯一 canary、反事实重跑、服务 PID 绑定 |
| 模型反复生成幻觉字段 | 预算消耗和错误载荷 | schema 拒绝、失败反馈、失败签名上限 |

## 17. 最终交付物

每个样本至少生成：

- device_fingerprint.json：设备和服务版本；
- entry_discovery.json：入口候选及源码/设备证据；
- protocol_contract.json：协议描述符、字段映射、守卫和假设；
- probe_result.json：合法探针的发送和回执；
- payload_manifest.json：HAP/native/CLI 实际载荷；
- input_influence.json：输入到危险参数的证据；
- oracle_result.json：before/during/after/refutation；
- dynamic_result.json：最终状态、失败类别和下一步建议；
- cleanup_result.json：设备清理和恢复记录。

最终验收报告按样本展示：版本是否匹配、服务是否稳定、入口和协议是否通过探针、实际发送内容、输入是否到达危险参数、观察到的安全效果，以及最终状态的理由。

## 18. 实施顺序总结

先做设备版本和服务预检；再做动态协议恢复；先发合法探针确认入口和字段；再发送单变量变异；用输入影响 oracle 确认危险参数受控；用漏洞类别 oracle 判断安全效果；清理并归档；最后重新评估全部 24 个样本。

DP-02 只能作为自动契约的回归基线，不能继续作为整个动态测试具备泛用性的证明。
